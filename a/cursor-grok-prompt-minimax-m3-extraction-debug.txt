## Context — what "MiniMax M3 extraction" actually means in this app

The app's itinerary extraction path currently uses **OpenRouter with the `minimax/minimax-m3:free`
model** as a temporary path, not direct Kimi API. The Welcome screen's "Try the screenshot sample
— extract with MiniMax M3" button triggers this flow. When you get Kimi credits and switch to the
Kimi API key, the app will use the direct Kimi API instead — but for tomorrow's demo, the
MiniMax path via OpenRouter is what's wired and needs to be debugged.

## What's known from prior work

- **OpenRouter adapter exists:** `server/openrouter-extract.mjs` (or equivalent) is pinned to
  `minimax/minimax-m3:free`.
- **Credential present:** OpenRouter API key is in `.env.local` (value not to be printed).
- **Extraction flow:** Upload/select screenshot → "Check my itinerary" → server calls OpenRouter
  → MiniMax M3 returns structured JSON → UI renders editable itinerary cards.
- **Prior evidence:** Historical live extraction evidence exists under `smoke-tests/extraction/`
  or `smoke-tests/gemini/` (from earlier direct Gemini work), but the current runtime path is
  MiniMax via OpenRouter.
- **No direct Kimi API wired yet:** The app does not currently call the Kimi API directly — that's
  a future switch once credits are available.
