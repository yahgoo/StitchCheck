## What StitchCheck is

A hackathon travel app: a traveller uploads a flight screenshot (or uses a built-in sample),
the app extracts the itinerary via MiniMax M3, evaluates whether a self-transfer connection
is at risk, and shows real flight alternatives from the Atlas Sandbox flight-search API — all
strictly read-only. It never books, pays, or issues tickets. Every screen ends with "No
booking, payment, reservation, or order created." The only traveller actions are "Keep
current itinerary" or "Switch to this plan" (a non-binding request, not a real booking).

## Architecture anchors (real files — verify current names/line numbers yourself)

- `app/src/App.tsx` — main screen orchestration (Welcome → Review/Trip → Options → Done).
  This file has been heavily modified in the last several hours across two sessions:
  (1) a "MiniMax visibility fix" adding Welcome-screen button hierarchy, extraction loading
  state, provenance tag, and provider-check-bar timing; (2) an Atlas-race fix serializing two

- `app/atlas-proxy.mjs` — Vite dev-server middleware proxying `/api/atlas/search` and
  `/api/atlas/verify` to the local `atlas-flight` CLI via `child_process.execFile`, with an
  allow-list (only search/verify forwarded, all write routes 404), 8s timeout, one retry on
  5xx/timeout only. Returns HTTP 502 with `{ error: <CLI code>, message: sanitizeError(...) }`
  on CLI failure.
- `app/src/atlas/client.ts` (or `app/src/lib/atlasClient.ts`) — throws `AtlasClientError(code,
  message, 502)` on proxy failure.
- `app/src/components/LiveAlternativesList.tsx` — new component (added in the persona-UX
  critique implementation pass) rendering the sorted/collapsed 20-offer KUL→SIN alternatives
  list with a "Verify and select plan" combined action.
- `app/src/components/UnbookedTicketPreviewLegSection.tsx` — pre-existing per-leg preview
  component with its own independent Atlas search+verify calls for the featured/expandable
  5-offer cards per leg.
- `app/src/components/MiniMaxProvenanceTag.tsx`, `MiniMaxOfflineNotice.tsx`,
  `app/src/data/minimax-visibility-copy.ts` — new components/copy from the MiniMax visibility
  fix.
- `app/src/components/ProviderStatusBar.tsx` — compact "Provider checks: N of 3 complete" bar,
  recently changed to not render before checks start and to never say "passed."

## Known issue history (do NOT rediscover from scratch — build on this)

1. **Issue A (resolved):** `atlas-flight` CLI intermittently failed with
   `SECURE_STORE_UNAVAILABLE` ("Secure credential storage is unavailable") — macOS
   Keychain/`keyring` contention. Confirmed via `atlas-flight doctor --json` passing when run
   alone (`DOCTOR_OK`) but failing under concurrent CLI invocations. This was diagnosed as
   PRE-EXISTING environment flakiness, not app-code caused, in an earlier session.
2. **Issue B (resolved, but see caveat):** A SECOND, related issue surfaced:
   "Live alternatives are unavailable. Service temporarily unavailable"
   (`SERVICE_TEMPORARILY_UNAVAILABLE` CLI error code). Root-caused this time as a REAL
   regression: on Options entry, `handleCheckMyTrip` called `performLiveSearchForConfirmed`
   (main KUL→SIN alternatives search) while a separate `useEffect` for unbooked previews
   ALSO fired immediately on `step === 'options'`, launching a second concurrent
   `atlas-flight` search for the same leg — causing secure-store contention under load. Fixed
   by: (a) setting `searchLoading` true before `setStep('options')`, and (b) gating the
   unbooked-previews effect until the primary search settles
   (`!searchLoading && (alternativesResult || searchError)`).
3. **Caveat explicitly flagged after Issue B's fix:** the fix was verified end-to-end on the
   READY-MADE sample path only (first load succeeded, 20 real offers, TR467 at USD 21.52). The
   SCREENSHOT-sample path (which also runs MiniMax extraction before reaching Options) was
   NOT independently re-walked after this fix — it was assumed to work because it "shares the
   same Options transition logic," but this was never actually observed.
4. **Current report: "app still not working"** — no further detail given. This could be:
   a. The exact same race as Issue B recurring (if the fix didn't fully eliminate all
      concurrent Atlas calls — e.g. `LiveAlternativesList.tsx`'s own fetch, or the
      per-leg `UnbookedTicketPreviewLegSection` calls, could still overlap with the primary
      search or with each other).
   b. A NEW issue specific to the screenshot-sample path (the never-independently-verified
      caveat above) — e.g. MiniMax extraction completing and the Options transition firing
      Atlas calls before extraction-related state has settled, similar in shape to Issue B
      but on a different path.
   c. A completely unrelated regression from the MiniMax-visibility-fix UI changes themselves
      (button hierarchy, loading state gating, provider-bar timing) breaking something
      unrelated to Atlas entirely.
   d. A build/typecheck failure or dev-server crash unrelated to any of the above (check this
      FIRST — it's the cheapest thing to rule out).
