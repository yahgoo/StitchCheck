# StitchCheck — Generate a Sample Itinerary Screenshot from Real Atlas Data for Upload Demo
# Cursor Agent — implement end to end, verify with a real extraction run

## Context

Today, "Try a sample itinerary" on the Welcome screen skips the extraction step entirely —
it loads a pre-structured itinerary directly, which is why MiniMax M3 always shows "offline"
in that path (there's no screenshot to extract from). This means judges/users never actually
see the upload → extraction (MiniMax) → correction → confirm pipeline in action unless they
manually create and upload their own screenshot.

Add a second, complementary demo shortcut: a generated sample itinerary IMAGE, built from
real Atlas Search data (not fabricated flight numbers/prices), that a user can click to
auto-load into the actual upload flow — exercising real extraction, not skipping it. This
directly demonstrates the multimodal extraction capability end to end for judges.

## Goal

Add a "Try sample itinerary screenshot →" (or similarly named) entry point on the Welcome
screen that:
1. Loads a pre-generated itinerary screenshot image (built once, ahead of time, from real
   Atlas flight data already observed in this project's live runs — e.g. KUL→SIN AK701 and
   SIN→BKK TR624, or similar real carrier/flight-number/price combinations already captured).
2. Feeds that image through the EXACT SAME upload → extraction (MiniMax) → review/correction
   → confirm pipeline used for a real user-uploaded screenshot — do not special-case or skip
   extraction for this path.
3. Results in MiniMax actually running and showing "live" (or "offline" only if genuinely
   unavailable, honestly reported) — proving the extraction step actually works, unlike the
   existing "Try a sample itinerary" shortcut.

## Absolute constraints

- The underlying flight data embedded in the generated image (carrier, flight number, route,
  times, price) MUST be real data already observed from Atlas Sandbox in this project (reuse
  values already captured in prior live runs, e.g. AK701 KUL→SIN USD 21.80, or TR624 SIN→BKK
  USD 107.10) — do not invent fictitious flight numbers/prices for this new asset.
- The generated image itself MUST be clearly a demo artifact, not a claim of a real booking —
  follow the exact convention already used for the existing GEM-01 two-leg demo fixture
  (check `app-fixture-contracts/` and any existing demo-screenshot assets for the established
  labeling pattern, e.g. "Demo fixture" / "local demo fixture" language) so it's consistent
  with existing provenance rules.
- Do not claim this image is a real airline ticket, confirmation email, or booking receipt in
  any UI copy — label it explicitly as a sample/demo itinerary image for testing extraction.
- Do not touch Atlas write routes, Nosana execution, route-continuity snapshot logic, or the
  existing "Try a sample itinerary" (structured-data) shortcut — this is a NEW, additional
  entry point, not a replacement.
- Do not fabricate a "live" extraction result if MiniMax is actually unavailable when this
  runs — report the real status honestly, same as everywhere else in the app.
- Do not weaken any existing test to force a pass.
- Do not touch video/narration/subtitle files.
- Do not commit/push.
