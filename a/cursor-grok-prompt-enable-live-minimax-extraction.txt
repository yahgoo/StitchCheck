## Context — what's broken right now

Per your earlier diagnosis:
- MiniMax M3 via OpenRouter is **wired**, but `DATA_MODE=offline` gates it off entirely.
- Even if flipped live, four failure modes would break the demo:
  1. **Snapshot happens BEFORE extraction** — confirmed itinerary snapshot (which feeds Atlas
     Search and the provenance pill) is taken from the fixture, not from MiniMax's output.
  2. **`date` vs `departureDate` schema mismatch** — MiniMax outputs `date`, UI expects
     `departureDate`. A valid MiniMax response gets marked as error after merge, or leaves
     `departureDate` empty.
  3. **`maxCalls: 1` per Vite lifetime** — first click might work, second click in the same
     dev session silently returns `call_limit_exceeded`.
  4. **Extraction errors have no traveller-visible message** — only provider-bar `unavailable` /
     `offline`.
