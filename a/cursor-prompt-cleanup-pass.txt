# Cursor Agent — investigate before fixing; distinguish "real bug" from "test needs updating"

## Context

The final pre-demo audit found 5 failing smoke-test suites (32/37 fully pass) and a set of
stale markdown docs describing the pre-consolidation UI. This pass resolves both, plus
double-click race and back-button gaps flagged as low-severity.

## Absolute constraints

- Do not touch Atlas write routes, Nosana execution, or the route-continuity/best-option/
  disclosure-dedup/screen-consolidation logic already verified working.
- Do NOT touch video, narration, or subtitle files. Markdown docs (README, handover notes,
  presenter scripts, rehearsal runbooks) ARE in scope — they are plain text, not the excluded
  media files.
- Do not weaken any test assertion just to force a pass — for each failure, first determine
  whether the app is wrong or the test is stale, then fix the one that's actually wrong.
- Do not commit/push.

## Step 1 — Investigate the missing module (do this FIRST, before touching tests)

- `extraction/gemini-3.7-routing-regression-tests.mjs`
- `extraction/interactions-api-offline-tests.mjs`

1. Search the repo for every reference to `direct-gemini-adapter` (imports, requires, docs).
2. Check git history / `.gitignore` to determine: was this file deleted, renamed, or never
   committed? Is it still imported anywhere in `app/src` or `core/` at runtime (i.e. does the
   live extraction path actually depend on it), or was it fully superseded by
   `extraction/openrouter-extraction-adapter-offline-tests.mjs` (which passes 20/20)?
3. Report which case it is. Only if the live app still depends on this module and it's

UI dropped the "Offline" qualifier inappropriately when actually offline, fix the UI. If the

## Step 5 — Low-severity UX gaps from the audit

1. **Double-click race on "Check my itinerary":** add a disabled/pending state on the button
   while the confirm transition is in flight, so a second click can't re-trigger navigation
   before the first completes.
2. **Browser back mid-flow:** at minimum, ensure back navigation doesn't leave the user on a
   broken/blank `other` state — either wire up minimal history support for the main steps, or,
   if that's too large for remaining time, intercept back navigation to redirect to Welcome
   cleanly rather than an undefined state. Report which approach you took.
